# 第七批预登记：gold 对数优势判据的留出验证

写于运行之前（2026-11-03）。以下定义和判定标准全部来自第六批（开发集），运行后不再修改。

## 数据：50 条 prompt，第六批没有用过

- **HDFS 25 条：** `len8k-hdfs-17…24`（8 条）、`len16k-hdfs-17…24`（8 条）、`copy-hdfs-16…24`（9 条，32K）。
  - 第六批用的是 `len8k/len16k-hdfs-0…16` 和 `copy-hdfs-0…15`。
  - `copy-hdfs-16…24` 在第四、五批的机制探针中出现过，但没有参与检索头的选择。
  - HDFS 原始日志只有约 2000 行，窗口之间有重叠。
- **路径在前的清单 25 条：** `copy-manifest_pf-0…24`（32K）。这是开发集中没有的数据源和格式，此前只用于自由生成。

## 条件

- BF16；
- 模拟 NF4；
- RTN 4-bit g128；
- Wanda 50%；
- FlashPrefill V1，α=0.08，只在预填充阶段使用，权重为 BF16。

## 固定的定义

- **检索头（第六批选定，不重新选）：** L23H11、L22H4、L22H7、L22H3、L22H1、L23H12、L22H25、L21H25。
- **每个 target 用哪个头：** 在这 8 个头中，取 BF16 下 lo 最大的那个，所有条件用同一个头。
- **lo：** lo = log(gold 行注意力 / 其他上下文行注意力)，在答案分叉 token 上做 teacher forcing 测量。
- **翻转：** BF16 用 teacher forcing 能抄对，压缩后抄错。
- **AUC 区间：** 按 prompt 做 1000 次 bootstrap，取 95% 区间。

## 主要判定（事先写定）

1. **压缩后 lo 能区分翻转：** 4 个权重压缩条件中，至少 3 个满足 AUC ≥ 0.70，且 95% 区间下界 > 0.5。
2. **BF16 lo 能事先预测：** 至少 3 个权重压缩条件满足 95% 区间下界 > 0.5。
3. **比全局指标强：** 每个权重压缩条件下，压缩后 lo 的 AUC 都高于上下文 KL 和上下文 NLL 上升。
4. **log n 关系：** 只用 HDFS 的 BF16 target，lo 对 log n 的斜率落在 [−1.5, −0.5]。

## 次要和探索性分析（不计入判定）

- **两个只用 BF16 的量对比：** BF16 lo 与 BF16 分叉 margin 谁更好。开发集上两者接近（0.71–0.74 vs 0.65–0.74）。
- **FlashPrefill 条件：** 只报告，不计入主要判定。
- **分数据源的 AUC：** HDFS 和清单分开报告。
